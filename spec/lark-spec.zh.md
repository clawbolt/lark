## 摘要

本文规定 Lark 语言。Lark 是一门静态类型的语言，采用值语义，带所有权检查和结构化并发，编译成 C。本文规定它的词法、语法、类型系统、所有权规则、程序在运行时能观察到的行为，以及这些静态规则要提供的安全保证。凡是已经形式化验证过的规则，本文都注明对应的 Lean 4 定理。

## 本文的状态

本文不是互联网标准轨道的规范，没有经过 IETF 或任何标准组织的审查。它由 Lark 项目发布，供编写 Lark 程序和实现 Lark 工具的人参考。本文采用 RFC 系列的格式约定 [RFC7322]，因为这些约定适合写精确、便于审阅的规范。

这是规范的第 0 版。它描述的是 2026 年 11 月时参考编译器 `lark1`（Lark 仓库里的 `compiler/*.lark`）接受的语言。以后的版本将作为新文档发布；本文除了改正错误以外不再修改。

这门语言是实验性的。所有权规则在一个核心演算上有机器检查过的可靠性证明（第 24 节），但编译器本身没有经过验证。

本文有英文版和中文版，两者内容相同；有出入时以英文版为准。

## 1. 引言

### 1.1. 范围

本文规定哪些源码是 Lark 程序，以及这些程序运行时做什么。范围包括语言本身和编译器认识的内置函数。标准库（`std/*.lark`）是用 Lark 写的，另有文档；除了语言用到它的地方（例如 `std/map` 用的 `hash` 协议），标准库不在本文范围内。

参考工具的命令行只在改变程序含义的地方提到（测试构建、发布构建、包的映射）。

### 1.2. 规范用语

本文的“必须”“不得”“应当”“不应当”“可以”分别对应 BCP 14 [RFC2119] [RFC8174] 里的 MUST、MUST NOT、SHOULD、SHOULD NOT、MAY，按那里的意思理解。这些词在第 3 节到第 23 节和附录 A 里有这个含义；在例子和说明性的段落里是普通的词。

对程序的要求（“程序不得……”）规定哪些源码是合法的。对实现的要求（“实现必须报错”）规定符合本规范的编译器怎样对待合法和不合法的程序。

### 1.3. 术语

- **程序**：交给编译器的一组源文件，加上它们直接或间接 import 的所有文件。
- **实现**：编译器加上它的运行时支持，把程序翻译成可执行文件。
- **编译错误**：违反本文的某条规则，实现必须在程序运行之前发现。程序有编译错误时，实现不得生成可执行文件。
- **panic**：不可恢复的运行时错误。panic 时向标准错误打印信息和调用栈，进程以退出码 101 结束（第 15 节）。
- **可复制类型**：使用时隐式复制一份的类型（第 5.4 节）。其他类型都是**移动类型**。
- **位置**：变量、位置的字段（`p.f`）或位置的元素（`p[i]`）。位置的**根**是它开头的那个变量。
- **借用**：对某个位置的引用，只在一次调用、一个 `match`、一个 `for` 循环或一个 `lock` 块期间存在。借用不能存储。
- **不返回**：因为控制流离开而不产生值的表达式（`return`、`break`、`continue`、`panic`、`exit`）。

### 1.4. 设计原则

本节是说明性的。Lark 的规则按以下三条原则取舍：

1. 高效是命门。默认的写法就应该快：不为没用到的功能付代价，开销在源码里看得见（复制要写 `.copy()`，分配和原子操作不藏在常用路径里）。安全检查能在编译时做就不放到运行时。
2. 简洁。同一件事只有一种写法。能由已有规则推出来的规则不加。
3. 简单但不简陋。常用的事（按字符处理字符串、报出所有错误、常见的运算）不需要绕路。

### 1.5. 和参考实现的关系

参考实现是 `lark1`，它能编译自己。类型检查在 `compiler/check.lark`，所有权检查在 `compiler/own.lark`，控制流离开作用域时释放值的代码是 `compiler/cg_expr.lark` 里的 `drop_jump`。

本文和 `lark1` 不一致时，说明其中一方有缺陷。已知的不一致列在附录 B。含义依赖于这类缺陷的程序不可移植。

## 2. 记法

语法用 ABNF [RFC5234] 书写。语法里所有带引号的字符串都区分大小写，相当于加了 [RFC7405] 的 `%s` 前缀。

词法（第 3 节）描述字节序列。语法（第 4 节到第 19 节和附录 A）描述 token 序列：token 之间的空白和注释忽略不计，只是换行可能产生 `NL` 这个 token（第 3.9 节）。语法里的 `ident`、`int-lit`、`float-lit`、`str-lit` 指的是 token。

`x *("," x) [","]` 这种形式的规则表示用逗号分隔的列表，最后可以多一个逗号。用换行、分号或逗号分隔的列表用 `sep` 规则：

```
sep = NL / ";" / ","
```

例子用等宽字体书写，是说明性的。

## 3. 词法

### 3.1. 源码

源文件是一串字节，应当是 UTF-8 [RFC3629]。文件以 UTF-8 的字节顺序标记（EF BB BF）开头时，实现必须忽略这三个字节；诊断里的列号仍然从 1 开始数。

非 ASCII 的字节只能出现在注释、字符串字面量和字符字面量里。每个源文件后面都隐含一个换行，所以一个文件的最后一行不会和下一个文件的第一行连在一起。

### 3.2. 注释和空白

注释以 `//` 开始，到行尾结束；没有块注释。空格、水平制表符和回车是空白。换行也是空白，但在它结束语句的地方除外（第 3.9 节）。

### 3.3. 标识符和关键字

```
ident       = ident-start *(ident-start / DIGIT)
ident-start = ALPHA / "_"
```

标识符只能用 ASCII 字符。下面这些标识符是保留的关键字，不得用作名字：

```
fn type enum interface const pub import if else match for in
return break continue true false take inout scope select
```

下面这些词只在所引章节说明的位置有特殊含义，其他地方是普通的标识符：`test`（第 19 节）、`extern`（第 22 节）、`shared` 和 `dyn`（第 5.1 节）、`Fn`（第 5.1 节）、`defer`（第 6.7 节）、`lock` 和 `as`（第 17.3 节）、`after` 和 `done`（第 17.2 节）。

名字 `_` 是丢弃用的名字（第 6.2 节）。`while` 和 `loop` 是普通的标识符；但它们被当作循环语句写时，参考实现会报错并给出 Lark 的写法，因为 Lark 没有这两种语句。

### 3.4. 整数字面量

```
dec-lit = DIGIT *(DIGIT / "_")
hex-lit = "0x" *"_" HEXDIG *(HEXDIG / "_")
oct-lit = "0o" *"_" ODIGIT *(ODIGIT / "_")
bin-lit = "0b" *"_" BIT *(BIT / "_")
ODIGIT  = %x30-37
```

下划线只用来分隔数字，没有值。这里的 `HEXDIG` 大小写字母都接受。

十进制字面量不得超过 9223372036854775807（`int` 的最大值）；`int` 的最小值写成 `-9223372036854775807 - 1`。十六进制、八进制、二进制字面量不得超过 64 位；正好 64 位时，表示具有这个补码位模式的 `int`，所以 `0xFFFF_FFFF_FFFF_FFFF` 是 -1。出现这个进制里不合法的字母或数字是编译错误。

### 3.5. 浮点字面量

```
float-lit = dec-lit "." DIGIT *(DIGIT / "_") [exponent]
          / dec-lit exponent
exponent  = ("e" / "E") ["+" / "-"] DIGIT *(DIGIT / "_")
```

十进制字面量后面跟 `.` 和一个数字时是浮点字面量；但这个字面量本身紧跟在 `.` 这个 token 后面时除外：`t.0.1` 里的数字是元组下标（第 7.6 节）。`1..5` 里的 `..` 是区间运算符。

### 3.6. 字符字面量

```
char-lit = "'" (char-byte / escape) "'"
```

`char-byte` 是 `\` 以外的任意一个字节。字符字面量表示一个字节，类型是 `int`；在期望 `u8` 的地方是 `u8`（第 5.6 节）。字面量里不止一个字节（例如多字节的 UTF-8 字符）是编译错误。

### 3.7. 字符串字面量和插值

```
str-lit = DQUOTE *(str-byte / escape / interp) DQUOTE
escape  = "\" ("n" / "t" / "r" / "0" / "e" / "\" / DQUOTE
              / "'" / "#" / "x" 2HEXDIG)
interp  = "#{" expression "}"
```

`str-byte` 是 `"` 和 `\` 以外的任意字节，但不包括紧跟着 `{` 的 `#`。字符串字面量可以跨行，换行是值的一部分。

转义的含义：`\n` 换行（10），`\t` 制表符（9），`\r` 回车（13），`\0` 零字节，`\e` ESC（27），`\xHH` 十六进制值为 HH 的字节，`\\`、`\"`、`\'`、`\#` 表示字符本身。其他转义是编译错误。不想开始插值时，`#{` 写成 `\#{`。

插值的含义见第 7.8 节。插值的结尾是数 `{` 和 `}` 字节找到的，由此带来的问题见附录 B。

### 3.8. 运算符和标点

```
+   -   *   /   %   +%  -%  *%
==  !=  <   <=  >   >=  &&  ||  !
&   |   ^   <<  >>  >>>
=   +=  -=  *=  /=  %=  &=  |=  ^=  <<=  >>=  >>>=
??  ?   .   ..  ->  =>  ,   :   ;
(   )   [   ]   {   }
```

切分 token 时取能匹配上的最长的运算符。回绕运算没有复合赋值（没有 `+%=`）。没有对应左括号的右括号是编译错误。

### 3.9. 语句的结束

换行结束语句，产生 `NL` 这个 token，但以下情况除外：

1. 最内层未闭合的括号是 `(` 或 `[`。只有在顶层和直接在 `{` 里面时，换行才有意义。
2. 换行之前的最后一个 token 是以下之一：`+ - * / % +% -% *% == != < <= > >= && || ! & | ^ << >> >>> = += -= *= /= %= &= |= ^= <<= >>= >>>= ?? , . .. -> => : ( [ {`。
3. 换行之后第一个非空白的字符是 `.`，并且后面不是另一个 `.`。这样方法调用链的每一行都可以以 `.名字` 开头。

连续的几个换行只产生一个 `NL`。分号也能分隔语句。由于第 2 条，把表达式续写到下一行时，二元运算符必须写在第一行的行尾。

## 4. 程序结构

### 4.1. 顶层的项

```
program  = *NL *(item *NL)
item     = import / ["pub"] decl / test-decl / extern-decl
decl     = fn-decl / type-decl / enum-decl / iface-decl
         / const-decl
import   = "import" str-lit
```

文件的顶层只能有上面这些项。项的顺序没有意义：可以先使用、后声明。`pub`（第 16 节）用于 `fn`、`type`、`enum`、`interface` 和 `const`；`extern` 块里的 `pub` 写在每个声明前面。

`import` 必须写在行首（第 1 列）。路径不带 `.lark` 扩展名。

### 4.2. 根模块和包的映射

命令行给出的所有文件构成**根模块**，共用一个名字空间。`import` 载入的每个文件是一个单独的模块（第 16 节）。

import 的路径这样解析：如果实现得到了包映射 `名字=目录`（`lark1` 里是 `-p 名字=目录` 选项），并且路径的第一段是这个名字，那么 `import "名字"` 载入 `目录/名字.lark`，`import "名字/x"` 载入 `目录/x.lark`。否则先相对于写 import 的文件所在的目录找，再相对于这个文件所在的包的根目录找。每个文件最多载入一次。

### 4.3. 入口

程序从 `fn main()` 开始执行，它没有参数，返回 `()`。为测试构建的程序（第 19 节）从生成的测试入口开始执行，可以没有 `main`。

## 5. 类型

### 5.1. 类型的写法

```
type      = base-type *("?" / "!" [base-type])
base-type = "shared" base-type
          / "dyn" ident
          / ("fn" / "Fn") "(" [type *("," type) [","]] ")"
            ["->" type]
          / "[" type "]"
          / "(" ")"
          / "(" type *("," type) [","] ")"
          / qual-ident ["[" type *("," type) [","] "]"]
```

`T!E` 里的错误类型 `E` 只在 `!` 后面紧跟标识符时才解析。后缀从左往右作用：`int?!` 是 `(int?)!`。`shared` 只作用于紧跟着的基础类型：`shared Node?` 是 `(shared Node)?`。`(A)` 和 `A` 是同一个类型；元组类型至少有两个元素。`dyn` 只在后面跟着标识符时、`Fn` 只在后面跟着 `(` 时才构成类型。

### 5.2. 内置类型

| 类型 | 含义 |
|---|---|
| `int` | 64 位有符号整数。`+ - *` 检查溢出，`+% -% *%` 回绕。 |
| `float` | 64 位二进制浮点数 [IEEE754]。 |
| `u8` | 字节（0 到 255）。能比较、能做 `& \| ^ !`，不能做算术。`[u8]` 是字节缓冲。 |
| `bool` | `true` 或 `false`。 |
| `str` | 不可变的字节串，带引用计数。 |
| `()` | 单元类型。没有结果的函数返回 `()`。 |
| `[T]` | `T` 的列表（可增长的数组）。 |
| `(A, B, ...)` | 两个或更多元素的元组。 |
| `T?` | 可选值：`Some(x)` 或 `None`。 |
| `T!E`、`T!` | 结果：`Ok(x)` 或 `Err(e)`。`T!` 就是 `T!str`。 |
| `S`、`S[A, ...]` | 结构体（第 5.3 节），按值存放。 |
| `E`、`E[A, ...]` | 枚举（和类型），按值存放，可以递归。 |
| `fn(A, ...) -> R` | 借用的函数，只能作参数类型。 |
| `Fn(A, ...) -> R` | 拥有的闭包，可以存储。 |
| `dyn I` | 实现了接口 `I` 的任意类型的值，装箱存放。 |
| `shared T` | 只读、带引用计数的共享值。 |
| `Chan[T]` | 任务之间的无界队列。 |
| `Mutex[T]` | 任务之间共享的值，只能在 `lock` 里修改。 |

### 5.3. 结构体和枚举

```
type-decl = "type" ident [tparams] "{" *sep *(field *sep) "}"
field     = ["pub"] ident ":" type
enum-decl = "enum" ident [tparams] "{" *sep *(variant *sep) "}"
variant   = ident ["(" [vfield *("," vfield) [","]] ")"]
vfield    = [ident ":"] type
```

结构体的字段之间、枚举的变体之间用换行、逗号或分号分隔。变体名必须以大写字母开头。变体的字段可以带名字（`V(名字: T)`），也可以不带（`V(T)`）。泛型结构体和枚举的类型参数不得带约束（第 12.2 节）。

### 5.4. 可复制类型和移动类型

可复制类型正好是 `int`、`float`、`u8`、`bool`、`()` 和 `str`。复制 `str` 只是把引用计数加一。其他类型都是移动类型：赋值、传递或返回移动类型的值时，值被移走（第 9 节）；要复制必须明确写 `.copy()`。

`Fn`、`shared T`、`Chan[T]`、`Mutex[T]` 的 `.copy()` 是把引用计数加一，得到指向同一个对象的句柄。有自定义 `drop`（第 13 节）的类型，以及包含这种类型的类型，不得复制。

### 5.5. 类型转换

类型之间没有隐式转换，只有两个例外。两者都只在有期望类型的地方适用：变量标注、函数结果、参数、字段、列表元素。

1. 期望 `T?` 或 `T!E` 的地方给了 `T`，自动包成 `Some` 或 `Ok`。
2. 期望 `dyn I` 的地方给了实现 `I` 的类型的值，自动装箱。

### 5.6. 整数字面量的类型

整数字面量（包括字符字面量）在期望 `u8` 的地方类型是 `u8`，这时必须在 0 到 255 之间；其他地方类型是 `int`。`u8` 和 `int` 之间要明确转换：`b.to_int()`，`n.to_u8()`（超出范围时 panic），`n.wrap_u8()`（取低 8 位），`n.try_u8()`（返回 `u8?`）。`s.to_bytes()` 和 `from_bytes(bs)` 在 `str` 和 `[u8]` 之间原样复制字节。

### 5.7. 相等

除函数类型以外，所有类型的值都能用 `==` 和 `!=` 比较，按值逐个元素比较。两个 `Fn` 值是同一个闭包时相等。类型有自定义的 `eq`（第 13 节）时用它。

## 6. 语句

```
block = "{" *NL [stmt *(1*(NL / ";") stmt) *(NL / ";")] "}"
stmt  = defer-stmt / for-stmt / ident ":" for-stmt
      / ident ":" type "=" expression
      / ident 1*("," postfix) "=" expression
      / expression [assign-op expression]
assign-op = "=" / "+=" / "-=" / "*=" / "/=" / "%=" / "&="
          / "|=" / "^=" / "<<=" / ">>=" / ">>>="
```

### 6.1. 声明和赋值

`x = v`：作用域里没有变量 `x` 时，声明新变量 `x`，类型是 `v` 的类型；已有时是给它赋值。`x: T = v` 是带标注的声明；给已经存在的变量写标注是编译错误。`p = v`（`p` 是字段或元素）给那个位置赋值。

### 6.2. 遮蔽和丢弃

内层作用域的声明不得重用外层作用域里变量的名字。`_` 除外：它可以声明任意多次，但不得读取。`_ = e` 求出 `e` 后丢掉结果。

### 6.3. 元组解构

`a, b = t` 把元组解构到新变量（或 `_`）里。解构到已有的变量是编译错误。

### 6.4. 复合赋值

`x op= v` 就是 `x = x op v`。目标可以是变量、字段或列表元素。目标是用户定义的类型时，运算符按协议函数解析（第 13 节）：`s += v` 就是 `s = add(s, v)`。

对 `str`，没有别的引用指向这个字符串时，`s += x` 和 `s = s + x` 原地追加，所以在循环里一段段拼字符串是线性时间的。

### 6.5. 块

块是表达式：最后一条语句是表达式时，块的值就是它的值；否则块的值是 `()`。`if`、`match`、`select`、`scope`、`lock` 也都是表达式。没有 `else` 的 `if` 的值是 `()`。

### 6.6. 不返回的表达式

`return`、`break`、`continue`、`panic(...)`、`exit(...)` 不返回。它们可以出现在任何需要值的位置，和任意类型的分支兼容。

### 6.7. defer 块

```
defer-stmt = "defer" block
```

`defer` 只在后面跟着 `{` 时才是语句。控制流离开包含 `defer` 语句的块时执行 defer 块：走到块尾，或者经由 `return`、`?`、`break`、`continue` 离开都算。循环体里的 defer 每轮执行一次。

几个 defer 块按相反的顺序执行，并和析构交错：defer 之后声明的值先销毁，然后执行 defer 块，再销毁 defer 之前声明的值，所以 defer 块里还能用它们。`return x` 的值在执行 defer 块之前就算好了。

defer 块用到的外层变量，在那个块结束之前不得移走；可以重新赋值或以 `&` 传递，defer 块看到的是离开时的值（规则 R21，第 9 节）。defer 块里不得有 `return` 或 `?`；里面的 `break`、`continue` 必须指向 defer 块里面的循环，这些循环不得带标签。闭包里不得写 `defer`。

`exit` 和 `panic` 不执行 defer 块，也不执行析构。有 defer 块生效时，调用自己的 `return f(...)` 不变成跳转（第 8.4 节）。

## 7. 表达式

### 7.1. 优先级

从低到高：

| 级别 | 运算符 | 结合 |
|---|---|---|
| 1 | `??` | 右 |
| 2 | `\|\|` | 左 |
| 3 | `&&` | 左 |
| 4 | `== != < <= > >=` | 不结合（不得连写） |
| 5 | `\|`（按位或） | 左 |
| 6 | `^` | 左 |
| 7 | `&`（按位与） | 左 |
| 8 | `<< >> >>>` | 左 |
| 9 | `+ - +% -%` | 左 |
| 10 | `* / % *%` | 左 |
| 11 | 一元 `-` 和 `!` | 前缀 |
| 12 | `.名字`、`.名字(...)`、`[下标]`、`?` | 后缀 |

位运算比比较结合得更紧，和 Rust 一样，所以 `x & 1 == 0` 是 `(x & 1) == 0`。

### 7.2. 算术

算术运算符两边必须是同一个类型。`+` 也用于拼接 `str`。`< <= > >=` 用于 `int`、`float`、`str` 和有自定义 `cmp` 的类型。`&&` 和 `||` 用于 `bool`，只在需要时才求右边的值。

`int` 的 `+`、`-`、`*` 和一元 `-` 溢出时 panic。`/` 和 `%` 向零取整；除以零 panic；`MIN / -1` panic；`x % -1` 是 0。`float` 的运算按 [IEEE754]，不 panic。

### 7.3. 位运算

`&`、`|`、`^` 用于 `int`（以及 `u8`）。一元 `!x` 对 `int` 是按位取反，对 `bool` 是逻辑非。`<<` 移出去的位丢掉；`>>` 左边补符号位；`>>>` 左边补 0。移位数不在 0 到 63 之间时 panic。`+%`、`-%`、`*%` 按 64 位补码计算，不检查溢出。没有无符号整数类型：这些运算符把 `int` 当作 64 个位，`>>>` 和回绕运算覆盖了无符号运算的需要。

### 7.4. 默认值运算

`a ?? b` 里 `a` 的类型是 `T?` 或 `T!E`；只在 `a` 是 `None` 或 `Err` 时才求 `b`。`T` 是 `int`、`bool`、`str` 或 `float` 时，`a` 可以是变量，里面的值复制出来。其他的 `T` 要求 `a` 是临时的值（例如函数调用的结果），里面的值直接移出来；`a` 是变量或字段时是编译错误，程序要写 `x.copy() ?? b` 或者用 `match take`。

### 7.5. 方法调用的写法

`x.f(a, ...)` 就是 `f(x, a, ...)`。`f` 的第一个参数是 `inout` 时，自动传 `&x`。按 `x` 的类型查找函数（第 12.5 节）。

### 7.6. 字段、元素和下标

`s.f` 读字段。`t.0`、`t.1` …… 读元组的元素。`x[i]` 读列表的元素（下标越界时 panic）；用户定义的类型调用 `index`，`x[i] = v` 调用 `set_index`（第 13 节）。

### 7.7. 构造和字面量

- `S(f: v, ...)` 构造结构体，字段的值按字段**声明**的顺序求值。
- `V(a, b)` 或 `V(名字: a)` 构造枚举的变体。没有字段的变体和结构体可以不写括号（`Nil`）。
- 不带括号的大写开头的名字表示没有字段的变体或结构体；小写开头的名字表示变量。
- 构造泛型类型时，类型实参从期望类型或字段推断。
- `[a, b]` 是列表字面量，`(a, b)` 是元组。空列表 `[]` 需要期望类型。
- 调用时可以给实参加标签（`f(x: 1)`），只用于结构体和变体的构造。

### 7.8. 字符串插值

`"...#{x}..."` 里，`int`、`float`、`bool`、`str` 类型的值直接转换。其他类型的值用 `fn show(x: T) -> str` 转换（第 13 节）。没有自定义 `show` 的列表、`T?`、元组按元素拼接，容器里的字符串加引号。结构体和枚举必须有 `show` 才能插值。

## 8. 函数

### 8.1. 声明

```
fn-decl = "fn" ident [tparams] params ["->" type] block
params  = "(" [param *("," param) [","]] ")"
param   = ["inout" / "take"] ident ":" type
```

省略 `-> R` 时结果类型是 `()`。函数体块的值就是结果；可以用 `return` 提前返回。

### 8.2. 参数的模式

| 写法 | 含义 | 调用处 |
|---|---|---|
| `x: T` | 只读借用。函数不得修改或移走 `x`，也不得以 `&` 传出去。 | `f(v)` |
| `inout x: T` | 可变借用，修改对调用者可见。 | `f(&v)` |
| `take x: T` | 转移所有权。调用之后不得再使用 `v`（可复制类型除外）。 | `f(v)` |

### 8.3. 重载

同名函数按**第一个**参数的类型区分。两个同名函数的第一个参数类型相同，或者都没有参数，是重复定义。普通函数优先于泛型函数。

### 8.4. 尾调用

函数在尾部调用自己，并且每个参数都是 `take`、`int` 或 `bool` 时，这次调用必须编译成跳回函数开头，不增加栈的深度。尾部指：函数体的值，处在尾部的 `if` 或 `match` 各分支的值，处在尾部的块的值，以及 `return f(...)`。在 `scope` 里、在闭包里、有 defer 块生效时不做这种变换。

## 9. 所有权

所有权规则在类型检查之后检查。这里把它们写成对程序的规则；编号 R1 到 R24 和可靠性证明（第 24 节）里用的编号一致。引导编译器和 `lark1` 执行相同的核心规则。

- **R1、R2（移动）**：移动类型的值赋给变量、作为 `take` 实参、放进构造的值或列表、作为返回值时被移走。被移走的变量在重新赋值之前不得使用。只有函数自己拥有的变量才能被移走：参数、`inout` 参数、借用的 `match` 绑定的名字、闭包捕获的变量都不行。
- **R3（不能从位置里移出）**：字段、列表元素、元组元素不得单独移走。程序要用 `.copy()`、`pop`、`replace(&x, 新值)`、`match take` 或者解构。重载的 `index` 除外，因为它返回的是新值。
- **R4、R5（求值模式）**：元组、列表、构造的元素，`take` 实参，`return` 的值和赋值的右边按拿走所有权检查；运算的两边、条件、下标、插值的值按借来看检查。值被借来看的 `if`、`match`、块，它们的分支按拿走所有权检查，因为分支的值是新的。
- **R6（inout 实参）**：`&p` 的实参必须是不经过 `shared` 的位置。它的根不得是只读的、被捕获的或被冻结的。在模块外，`&p` 不得经过有私有字段的结构体的字段。
- **R7（排他）**：传 `&p` 时，`p` 的根不得出现在同一次调用的其他实参里，包括经由捕获了它的闭包出现。不是位置的可复制类型的实参（调用结果、构造出来的值）除外；按 `take` 传的 `str` 也除外，它会先被复制。
- **R8（实参里的移动）**：一个实参移走的变量（直接移走，或者在这个实参里的块、`if`、`match` 里移走）不得出现在别的实参里。
- **R9（实参的顺序）**：实参按书写顺序求值和检查。不返回的调用之后的代码不可达。
- **R10（分支合并）**：`if` 或 `match` 之后，任何一个分支里移走的变量都算移走。以不返回结束的分支不参与合并。
- **R11（冻结）**：借用的 `match e`、`for x in e` 和 `lock` 块期间，`e` 的根被冻结：不得赋值、移走或以 `&` 传递。`match take e` 拿走 `e`，不冻结。
- **R12、R13（循环）**：循环体可以移走循环外声明的变量，但必须在本轮结束之前、以及每个 `continue` 之前重新赋值。循环之后的状态是进入时、本轮结束时和每个 `break` 处的状态的并；`break L`、`continue L` 算在标签为 `L` 的那层循环。
- **R14（return）**：`return` 拿走它的值，之后的代码不可达。
- **R15（循环条件）**：`for 条件 { ... }` 的条件每轮都求值，属于这个循环。
- **R16（赋值）**：`x = e` 先检查 `e`；`x` 不得是只读的、被捕获的或被冻结的。赋值之后 `x` 又有了值。
- **R17（给位置赋值）**：`p = e`（`p` 是字段或元素）时，`p` 的根满足 R6，并且不得已被移走，因为不能往空位里写一部分。
- **R18 到 R20（闭包）**：见第 14 节。
- **R21（defer）**：见第 6.7 节。
- **R22 到 R24（并发）**：见第 17 节。

值在离开作用域、被覆盖、或者装着它的容器被销毁时销毁。`return`、`break`、`continue` 销毁它们离开的作用域里的值。被移走后的空位不会再被销毁一次。

## 10. 模式匹配

```
match-expr = "match" ["take"] expression "{" *sep
             [arm *(1*sep arm) *sep] "}"
arm        = pattern "=>" expression
pattern    = pat1 *("|" pat1)
pat1       = ident ":" type
           / qual-ident ["(" [pattern *("," pattern) [","]] ")"]
           / "(" pattern 1*("," pattern) [","] ")"
           / str-lit / ["-"] int-lit / "true" / "false"
```

分支从上到下尝试，执行第一个匹配上的。所有分支必须是同一个类型，不返回的分支除外。

模式有：`_`（匹配任何值）；小写开头的名字（绑定这个值）；整数（可以带负号）、`true`、`false`、字符串字面量；变体 `V` 或 `V(p, ...)`，可以带模块限定；元组 `(p, q, ...)`；“或”模式 `p | q | ...`，任何一个选项匹配就算匹配，不得绑定名字。模式可以任意嵌套（`Some(1 | 2)`）。类型模式 `名字: T` 见第 12.4 节。

能匹配的有枚举、`T?`、`T!E`、`int`、`bool`、`str` 和元组；`float` 不能匹配。穷尽检查按模式矩阵逐列进行；对整数和字符串的匹配必须有一个通配的分支。

**借用匹配**（默认）把名字绑定为指向被匹配值内部的只读引用，可以任意深；`match` 期间被匹配的值被冻结。**拥有匹配** `match take x` 拿走 `x`，把字段的所有权交给绑定的名字。它只拆一层，所以字段的模式必须是名字或 `_`。有自定义 `drop` 的枚举不得 `match take`。

## 11. 循环

### 11.1. 写法

```
for-stmt = "for" block
         / "for" for-bind "in" expression [".." expression] block
         / "for" expression block
for-bind = [ident ","] (ident / "(" ident *("," ident) [","] ")")
```

`for { ... }` 是无限循环。`for 条件 { ... }` 在条件为真时继续。`for i in lo..hi` 遍历从 `lo` 到 `hi`（不含 `hi`）的整数。`for` 后面是一个标识符、再后面是 `in` 或 `,` 时，或者是 `(`、标识符和 `,` 时，按 `for x in` 解析。

### 11.2. 遍历的来源

`for x in 来源 { ... }` 接受三种来源：

1. 列表。`x` 是每个元素的只读借用；循环期间列表被冻结。
2. 迭代器：有 `fn next(inout it: T) -> E?` 的类型。迭代器被移进循环；每次 `Some(v)` 时 `v` 归 `x` 所有，`None` 时结束。循环结束时销毁迭代器。
3. 借用遍历：没有 `next`、但有 `fn iter_len(x: T) -> int` 和 `fn iter_at(x: T, i: int) -> E` 的类型（两个都只读）。先调用一次 `iter_len`；每轮 `x` 拥有 `iter_at(v, i)` 返回的值。循环期间 `v` 被冻结，之后照常可用。

`for x in 列表` 的列表和 `for i in a..b` 的区间只在进入循环之前求一次值，属于外面的代码。

### 11.3. 带序号和元组的遍历

`for i, x in 来源` 同时给出从 0 开始的序号；`i` 是新的 `int` 变量。整数区间不得带序号。`for (a, b) in 来源` 和 `for i, (a, _) in 来源` 把元组元素拆开；每一项是名字或 `_`，个数必须和元组的元素个数相同。拆出来的名字是指向元素内部的只读借用，相当于 `for _e in xs { match _e { (a, b) => { ... } } }`。序号变量和元素变量必须用不同的名字。

### 11.4. 带标签的循环

`名字: for ...` 给循环加标签。`break 名字`、`continue 名字` 跳出或继续那一层循环；不带标签的 `break`、`continue` 指最内层的循环。标签不得和外层循环的标签重名，`break`、`continue` 写的名字必须是外层的某个标签。闭包里看不到外面的标签。这样跳出循环时，照常销毁值、执行 defer 块。

## 12. 泛型与接口

### 12.1. 泛型函数

```
tparams = "[" tparam *("," tparam) [","] "]"
tparam  = ident [":" bound *("+" bound)]
bound   = ident ["[" ident "]"]
```

调用时从不写类型实参，而是从实参的类型推断；实参推断不出的类型参数用期望的结果类型补上；还推断不出时是编译错误。实参先在没有期望类型的情况下检查，所以泛型位置上的实参不会自动包成 `Some`，也不能直接传 `[]` 或 `None`。

泛型函数单态化：每组类型实参生成一份代码。模板本身不检查，每个实例在代换之后检查，报错指向模板里的位置。泛型函数可以按第一个参数重载：先找第一个参数类型完全相同的普通函数，再找第一个参数的模式能对上的泛型函数。

### 12.2. 泛型类型

`type Pair[A, B] { ... }` 和 `enum List[T] { ... }` 声明泛型类型。每组类型实参实例化成一个普通类型，在诊断里显示成 `List[int]`。它们的类型参数不得带约束。

### 12.3. 接口和约束

```
iface-decl = "interface" ident "{" *sep
             *("fn" ident params ["->" type] *sep) "}"
```

接口列出一组方法，用 `Self` 表示实现它的类型。接口按结构匹配：对每个方法，把 `Self` 换成某个类型之后，存在参数模式、参数类型、结果类型都相同的函数，这个类型就实现了接口。没有 `impl` 声明。约束在调用处检查，报错指出缺少哪个函数。

内置的约束有：`Eq`（能用 `==` 比较，除函数类型外都满足）；`Ord`（`int`、`str`、`float`，以及有 `cmp` 的类型）；`Iter[T]`（元素为 `T` 的列表、迭代器或借用遍历）；`Next[T]`（只接受有 `next` 的迭代器）。

### 12.4. dyn 值

只有每个方法的第一个参数都是只读的 `Self`、并且 `Self` 不出现在其他位置的接口才能用作 `dyn I`。`dyn` 值拥有装箱的值；复制它会复制装箱的值。`x.m()` 经由函数表分派。

取回具体类型有两种办法：在对 `dyn` 值的 `match` 里用类型模式 `r: Rect =>`（`r` 只读地借用装箱的值，可以写成 `_`）；或者用 `d.downcast()`，它的类型来自期望的 `T?`，装的是 `T` 时得到 `Some(副本)`，否则得到 `None`。因为 `dyn` 是开放的，这样的 `match` 必须有 `_` 分支。类型模式和 downcast 里的类型必须实现了这个接口。

两个 `dyn` 值的具体类型不同时不相等；相同时用那个具体类型的 `==`。具体类型不能比较时，比较在运行时 panic。不支持对 `dyn` 值 `match take`，也不支持装入有自定义 `drop` 的值。

### 12.5. 方法的查找

`x.f(...)` 按以下顺序找 `f`：

1. 定义 `x` 的类型的模块；
2. 当前模块；
3. 根模块；
4. 以上都没有、`f` 也不是内置函数时：import 的模块里的“扩展方法”，即第一个参数是带 `Iter` 或 `Next` 约束的类型参数、或者是列表 `[T]` 的 `pub` 泛型函数。两个模块都有时是编译错误。

## 13. 协议函数

编译器在特定的语法处隐式调用以下函数。它们按第一个参数的类型重载，签名在定义处检查。除注明的以外，参数都是只读的。

| 函数 | 调用的时机 |
|---|---|
| `add sub mul div rem(a, b)`、`neg(a)` | 左操作数是用户定义的类型时的 `+ - * / %` 和一元 `-`。第二个参数可以是别的类型。 |
| `cmp(a: T, b: T) -> int` | `< <= > >=`；让 `T` 满足 `Ord`。 |
| `eq(a: T, b: T) -> bool` | `==` 和 `!=`，以及列表、`T?`、map 的键里的比较。 |
| `index(x: T, i: K) -> V` | `x[i]`。结果是新的值，不是位置。 |
| `set_index(inout x: T, i: K, take v: V)` | `x[i] = v`；`x[i] op= v` 先读后写。 |
| `show(x: T) -> str` | 字符串插值。 |
| `hash(x: T) -> int` | `std/map` 和 `std/set` 的键。 |
| `next(inout it: T) -> E?` | `for x in it`。 |
| `iter_len(x: T) -> int`、`iter_at(x: T, i: int) -> E` | 借用遍历。 |
| `drop(inout x: T)` | 值被销毁时。不得直接调用。 |
| `from(take e: E1) -> E2` | `?` 两边的错误类型不同时。 |

`drop`、`from`、`main`、`eq`、`cmp`、`next` 和所有接口方法的名字在生成的代码里不加模块前缀，所以模块里的泛型代码能找到根模块里为用户类型写的实现。

一个类型最多只能有一个 `drop`。有 `drop` 的类型以及包含它的类型不得复制；`drop` 里不得给 `x` 整体赋值。用了这些名字的函数，不管定义在哪里都被当作协议函数，并按协议函数检查签名。不打算实现协议的函数不应当用这些名字。

## 14. 闭包

```
closure = "|" [ident *("," ident) [","]] "|" expression
        / "||" expression
```

参数类型来自期望的函数类型，结果类型从闭包体推断。

- **R18**：闭包体单独检查，因为它可能执行任意多次，也可能一次都不执行；它不改变外面的所有权状态。捕获的变量在闭包体里是只读的，不得移走。
- **R19**：闭包里不得写 `return`、`break`、`continue`、`?`、`defer`、`scope` 或 `lock`。
- **R20**：`Fn` 闭包不得捕获 `fn` 参数，也不得捕获有自定义 `drop` 的值。

**借用的闭包**传给 `fn(...) -> R` 参数。它按只读引用捕获变量，环境在栈上，不分配内存。在排他性规则 R7 里，它算作用到了它捕获的每一个变量。

**拥有的闭包**的类型是 `Fn(...) -> R`，可以存进变量、字段、列表，可以作为返回值，也可以交给别的任务。创建时把捕获的变量复制进堆上的环境，环境只读、带引用计数。`Fn` 值可以传给 `fn(...)` 参数。调用必须通过变量或参数；存在字段里的 `Fn` 要先读到变量里。

需要函数类型的地方，可以直接写函数名 `f` 作为值。它等于 `|a, b| f(a, b)`，生成一个什么都不捕获的闭包。`f` 不得是泛型函数，参数必须都是只读的，参数类型和结果类型必须和期望的一样；名字有重载时，按期望的第一个参数类型选择。传给泛型函数时，函数名在其他实参之后检查；它既不是重载也不是泛型时，它的签名参与类型参数的推断。

## 15. 错误处理

可恢复的错误用 `T!E`，`E` 可以是除 `()` 和函数类型以外的任意类型。可选的值用 `T?`。

`e?` 的类型是 `T`，规则如下。`e` 的类型是 `T?` 时，所在的函数必须返回某个 `U?`，`None` 时直接返回 `None`。`e` 的类型是 `T!E1` 时，所在的函数必须返回某个 `U!E2`，`Err` 时返回这个错误；`E1` 和 `E2` 不同时先用 `from` 转换。`scope` 块和闭包里不得使用 `?`。

返回 `()!` 的函数可以不带值地 `return`，走到结尾也表示成功。期望 `()!` 的 `if`，一个分支的类型是 `()!`、另一个分支没有值时，没有值的分支就是 `Ok()`。成功的 `()!` 结果匹配时写 `Ok` 或 `Ok(_)` 都可以。

`T!E` 类型的值不得丢掉：把它作为语句、作为 `()` 函数的结尾、循环体的结尾或分支的结尾都是编译错误。程序要用 `?` 或 `match` 处理它，或者写 `_ = ...` 明确丢掉。自动包成 `Ok` 的值不算。没有 `else` 的 `if`，分支以 `T!E` 的值结尾时是编译错误，因为这个结果会被悄悄丢掉。

不可恢复的错误用 `panic(信息)`。下标越界、整数溢出、除以零、`assert` 失败也会 panic。panic 时先刷新标准输出，打印信息和调用栈，以退出码 101 退出。`exit(n)` 以退出码 `n` 结束进程，不打印调用栈。

## 16. 模块与可见性

- 模块名是文件名（不带扩展名）。不得有两个同名的模块。
- 只有在 import 了模块 `m` 的文件里，限定名 `m.x` 才指模块 `m` 里的项 `x`；在这样的文件里，`m` 不得用作变量名。在别的文件里 `m` 是普通的名字。使用某个模块的每个文件都必须自己 import 它。
- 在模块外，模块里的项写成 `模块.名字`（`geo.Vec2`、`map.new()`）；在模块内直接写名字。查找名字时先找当前模块，再找根模块。
- **项**：模块里只有 `pub` 的项（`fn`、`type`、`enum`、`interface`、`const`）能在别的模块里使用。根模块的文件之间互相可见。
- 模块里定义的结构体的**字段**默认是私有的，只在本模块可见。`pub` 字段在模块外可以读。
- 对至少有一个私有字段的结构体，在模块外不得给 `pub` 字段赋值、复合赋值或以 `inout` 传递（包括方法调用时自动加的 `&`），也不得在模块外构造这个结构体。字段全是 `pub` 的结构体在哪里都能修改。整个值的赋值和传递不受限制。枚举变体的字段总是公开的。
- 变体按它所属的枚举所在的模块查找；模式里的模块限定可写可不写。
- 没有 `import ... as`，也不能只导入部分名字。

```
qual-ident = ident ["." ident]
```

只有第一个标识符是当前文件 import 的模块名时，才按两段的形式解析。

## 17. 并发

### 17.1. scope 和任务

`scope { ... }` 是结构化并发的边界。在它里面，`spawn(f, x)` 创建一个运行 `f(x)` 的任务；块要等它 spawn 的所有任务都结束才结束。

- **R22**：`spawn` 必须直接写在 `scope` 块里。`f` 必须是普通函数（不是闭包），正好有一个 `take` 参数，没有结果；`x` 被移进任务。
- 可以用 `return`、`?`、`break`、`continue` 离开 `scope` 块。离开时先销毁沿途的值，再等块里的任务结束，然后跳转。
- 值在任务之间只有三种传法：移过去；用 `shared` 只读共享；放进 `Mutex`。
- **R24**：`shared` 值的内容是只读的（不得经由它赋值或以 `&` 传递），`shared` 值里不得装 `Mutex` 或 `Chan`。

### 17.2. 通道和 select

`chan()` 创建 `Chan[T]`。`send(v)` 把 `v` 移进队列。`recv()` 返回 `T?`：队列为空时等待，直到有值到来，或者除自己以外的所有持有者都释放了这个通道，这时返回 `None`。没有 `close`。

```
select-expr = "select" "{" *sep [sel-arm *(1*sep sel-arm) *sep]
              "}"
sel-arm     = ident "<" "-" expression "=>" expression
            / "after" expression "=>" expression
            / "done" "=>" expression
```

`select` 等待几个通道里最先有值的那个。`after` 分支（以毫秒计的超时）最多一个，`done` 分支最多一个，它在所有通道都结束时执行。有 `done` 分支时 `select` 可以有值，否则每个分支的类型都是 `()`。

### 17.3. 互斥量

```
lock-expr = "lock" expression "as" ident block
```

`lock` 只在后面跟着标识符时才开始一个 lock 块。`mutex(v)` 创建 `Mutex[T]`；`.copy()` 得到同一个互斥量的句柄。里面的值只能在 `lock m as x { ... }` 里使用。

- **R23**：`m` 必须是位置，块里它的根被冻结。块里 `x` 相当于 `inout` 参数：能修改，能以 `&x` 传下去，不能移走。块结束时解锁。块的值就是 `lock` 表达式的值，必须是副本。
- 可以用 `return`、`?`、`break`、`continue` 离开 lock 块，跳转之前先解锁。闭包里不得写 `lock`。
- 任务拿着锁时可以等待。同一个任务再锁自己已经锁着的互斥量时，进程报错退出。两个任务按相反的顺序锁两个互斥量会死锁；不检测死锁。

### 17.4. 调度

任务是有自己的栈的协程，由运行时放到若干个系统线程上运行（`lark1` 里是 `LARK_PROCS` 个，默认是 CPU 核数）。第一次 `spawn` 时才启动调度器；不用并发的程序不为并发付任何代价。

任务不被抢占，只在等待的地方让出：`recv`、`select`、`scope` 的结尾、`sleep_ms`、等着 `lock`，以及 `std/net` 的读、写和 accept。阻塞的文件、管道、终端读写，`os.shell`，`net.connect` 和 `extern "c"` 函数等待时占着一个系统线程。

用了并发以后，socket 应当用 `std/net` 的 `close` 关闭（或者离开作用域时自动关闭）。直接经由 `extern "c"` 关闭的 socket 运行时不知道，以后在这个描述符号上的等待可能卡住。

## 18. 常量

```
const-decl = "const" ident "=" expression
```

常量的值在编译时求出，类型是 `int`、`bool`、`str` 或 `float`。表达式里只能有字面量、其他常量、算术、比较、逻辑运算和字符串的 `+`，不得调用函数。`float` 常量只支持 `+ - * / %`。循环定义、除以零、溢出是编译错误。

常量不得赋值，也不得作为 `inout` 传递。局部变量优先于同名的常量。常量和类型、函数、变体共用一个名字空间。

## 19. 测试

```
test-decl = "test" str-lit block
```

`test "名字" { ... }` 声明一个没有参数的测试。普通构建时检查测试但不运行。测试构建（`lark1 --test`）时，实现生成一个运行全部测试的入口。只收集命令行给出的文件里的测试，测试的名字必须互不相同。

每个测试在单独的子进程里运行，所以失败（panic、exit 或崩溃）只影响这一个测试。测试的输出只在失败时显示。测试程序的第一个命令行参数按名字过滤测试。

`assert(条件)` 在条件为假时 panic。`assert_eq(a, b)` 要求两边是同一个类型，这个类型必须能比较、能插值；失败时显示两边的值。

## 20. 诊断

本文不规定信息的措辞；`lark1` 用中文报告。符合本规范的实现必须做到以下几点：

- 错误必须指明文件、行和列。`lark1` 打印 `文件:行:列: 错误：信息`，然后是源码行和指向那一列的 `^`。
- 在函数体里，实现应当报告不止一处错误：`lark1` 跳过出错的语句，从头再检查一遍函数体，最多报告 10 处，这样一处错误不会引出连带的错误。有类型错误的函数跳过所有权检查。语法错误、类型声明和函数签名里的错误一次只报告一处。
- 对未定义的名字、类型、字段、变体，实现应当按编辑距离提示最接近的可用名字。
- 警告不影响编译（`lark1` 里用 `-w` 关闭）。实现应当对没用到的变量、不会执行的代码、没用到的 import、没用到的非 `pub` 函数和类型给出警告。以 `_` 开头的名字不警告，标准库里的警告不显示。
- 实现可以限制嵌套的深度。`lark1` 拒绝超过 256 层的括号和块嵌套，以及超过 1000 层的语法树，并提示把长的运算链拆开。

## 22. 调用 C 函数

```
extern-decl = "extern" str-lit "{" *sep
              *(["pub"] "fn" ident params ["->" type] *sep) "}"
```

`extern` 后面的字符串必须是 `"c"`。`extern "c"` 块只写签名，声明 C 库里的函数；写了函数体是编译错误。调用的写法和普通函数一样，调用的是 C 里同名的符号。

- 签名里能用的类型有：`int`（C 的 `int64_t`）、`c_int`、`c_uint`、`c_long`、`c_ulong`、`usize`、`isize`、`float`（C 的 `double`）、`bool`、`u8`、`str`（C 的 `const char*`）和 `[u8]`（只能作参数，传数据的指针）。结果类型还可以是 `()`。
- C 的整数类型只在 `extern` 块里有意义，在 Lark 这边都是 `int`。传给 C 的值检查范围，超出时 panic；C 返回的无符号数放不进 `int` 时也 panic。
- `str` 按以零结尾的字节传递；字符串中间的零字节会让 C 那边提前结束。C 返回的字符串复制成新的 `str`，`NULL` 当作空串。C 拥有的内存不归 Lark 管理。
- 参数都是只读的；只有 `[u8]` 可以是 `inout`，让 C 往缓冲区里写。C 写入的字节数不得超过列表的长度，这由调用方保证。
- 不支持可变参数的函数、回调、结构体和指针参数，以及头文件里的宏和 inline 函数。默认只链接 C 标准库。

使用 `extern "c"` 的代码不在第 24 节的安全保证之内。

## 23. 对实现的要求

### 23.1. 求值和释放的约定

第 24 节的可靠性证明假定生成的代码具有以下性质。符合本规范的实现必须做到：

| 编号 | 要求 |
|---|---|
| A1 | 实参和构造的字段按书写顺序求值。 |
| A2 | 移走一个值后，原来的位置变成空位；销毁空位什么也不做。 |
| A3 | 临时值（调用的结果、借用 `match` 的被匹配值）活到所在的语句或 `match` 结束。 |
| A4 | 控制流离开作用域时从里到外进行：销毁每一层的值，按相反的顺序执行这一层的 defer 块，给 `lock` 块解锁；离开 `scope` 块时最后等它的任务结束。 |
| A5 | `str` 的引用计数不是 1 时，修改之前先复制。 |
| A6 | 有任务在运行时，引用计数用原子操作更新。 |

### 23.2. 表示方式（说明性）

本节描述 `lark1`。它生成 GNU C11 [C11] 代码，只依赖 `runtime/lark_rt.h`。

- 结构体和元组按值存放。枚举按值存放，tag 从 1 开始，0 表示已移走。`T?` 存放为 `{ some, v }`。经由值字段包含了自己的枚举或 `T?` 放在堆上。列表是 `{ data, len, cap }`。
- 移动是按位复制，然后把原来的位置清零，所以运行时不需要“已移走”的标记。有 `drop` 的结构体带一个隐藏的存活标志。
- `T!E` 按值存放为 `{ set, ok, val, err }`，所以返回结果不用分配内存。`fn(...)` 是 `{ 函数指针, 环境指针 }`；`dyn I` 是 `{ 堆上的值, 函数表 }`。
- 泛型单态化，没有装箱，也没有运行时类型信息。
- panic 时打印调用栈，每个函数一帧（函数名、文件、当前行）。`--release`，或者编译 C 代码时加 `-DLK_NOTRACE`，关闭调用栈。加 `-DLK_UNCHECKED` 编译会关闭溢出检查和移位数检查，移位数只取低 6 位。用 `-DLK_UNCHECKED` 编译的程序不符合第 7.2 节。
- 任务的栈是 1 MiB（用到的页才占内存），下面有一页保护页。

## 24. 可靠性与形式化验证

### 24.1. 保证

静态规则要提供以下保证。设程序通过了类型检查和所有权检查，没有使用 `extern "c"`，编译时没有加 `-DLK_UNCHECKED`。那么程序运行只有这几种结局：正常结束；panic 或调用 `exit`；一直运行下去（包括死锁）；栈溢出。并且运行的每一步都满足：

1. **不读空位**：读到的变量、字段、元素都有值。
2. **每个值恰好释放一次**：在离开作用域、被覆盖、或者所在的容器被释放时释放。（不算引用计数成环的情况。）
3. **借用期间不变**：只读借用指向的值，在借用期间不会被修改、移走或释放。
4. **排他**：`inout` 借用期间，同一个值不会经由别的路径被读或写。
5. **没有数据竞争**：两个任务不会同时访问同一个值，除非两边都只读（`shared`），或者都在同一个互斥量的 `lock` 块里。

不在保证之内的有：经由 `extern "c"` 调用的 C 代码、`-DLK_UNCHECKED`、死锁、栈溢出，以及经由 `os.shell` 这类函数运行的外部程序。编译器本身的正确性（生成的 C 是否忠实实现这些规则）没有证明；第 23.1 节的要求 A1 到 A6 在证明里当作假设，用差分测试检查。

表里的定理都已在 2026 年 11 月证完。`formal/` 里的其他文件证明标准库模块和实验性 TLS 实现的性质，不属于语言的定义。

### 24.3. 证明的局限

证明针对一个核心演算 Lark-core，它只保留和所有权有关的特性。泛型、接口、`dyn`、模块和可见性、重载、协议函数、常量在类型检查时就消掉了，没有建模。规则 R7 和 R11 只看根变量，这是保守的：`f(&a.x, &a.y)` 被拒绝，虽然两个字段并不重叠。

## 25. 安全方面的考虑

对满足条件的程序，第 24.1 节的保证排除了几类内存错误。但它不等于程序是安全的，而且它的条件很容易越出：

- **`extern "c"`**：C 代码可以违反第 24.1 节的每一条性质。传给 C 的 `str` 在第一个零字节处结束，由不可信的输入拼出来的文件名或命令可能因此改变含义。越过 `inout [u8]` 缓冲区的末尾写入是未定义行为。
- **不检查的构建**：`-DLK_UNCHECKED` 让整数溢出悄悄回绕。靠溢出 panic 保证正确的代码（例如计算大小）会失去这层保护。
- **拒绝服务**：整数溢出、下标越界、断言失败都会 panic，结束整个进程。处理不可信输入的程序应当先校验输入，而不是依赖 panic。不检测死锁；任务的栈限制在 1 MiB，用完时进程以段错误结束，没有诊断。
- **时间**：语言不保证任何操作的耗时与数据无关。用 Lark 写的密码学代码不能指望编译器保持常数时间的行为。
- **退出的路径**：`exit` 和 `panic` 不执行 defer 块和析构。无论如何都要做的清理（例如删除临时文件、恢复终端）要用标准库的 `os.at_exit`。
- **外部程序**：`os.shell` 这类函数运行别的程序，那些程序在语言之外。字符串插值不做任何转义。
- **编译器的限制**：第 20 节的嵌套限制让编译器面对恶意构造的源码时不会耗尽栈。编译器没有经过验证（第 24.1 节）。

## 附录 A. 完整语法

本附录汇总第 4 节到第 19 节的语法，词法规则见第 3 节。语法有歧义的地方，按所引章节里的说明处理。

```
program    = *NL *(item *NL)
item       = import / ["pub"] decl / test-decl / extern-decl
decl       = fn-decl / type-decl / enum-decl / iface-decl
           / const-decl
import     = "import" str-lit
sep        = NL / ";" / ","

fn-decl    = "fn" ident [tparams] params ["->" type] block
tparams    = "[" tparam *("," tparam) [","] "]"
tparam     = ident [":" bound *("+" bound)]
bound      = ident ["[" ident "]"]
params     = "(" [param *("," param) [","]] ")"
param      = ["inout" / "take"] ident ":" type
type-decl  = "type" ident [tparams] "{" *sep *(field *sep) "}"
field      = ["pub"] ident ":" type
enum-decl  = "enum" ident [tparams] "{" *sep *(variant *sep) "}"
variant    = ident ["(" [vfield *("," vfield) [","]] ")"]
vfield     = [ident ":"] type
iface-decl = "interface" ident "{" *sep
             *("fn" ident params ["->" type] *sep) "}"
const-decl = "const" ident "=" expression
test-decl  = "test" str-lit block
extern-decl = "extern" str-lit "{" *sep
             *(["pub"] "fn" ident params ["->" type] *sep) "}"

type       = base-type *("?" / "!" [base-type])
base-type  = "shared" base-type / "dyn" ident
           / ("fn" / "Fn") "(" [type *("," type) [","]] ")"
             ["->" type]
           / "[" type "]" / "(" ")"
           / "(" type *("," type) [","] ")"
           / qual-ident ["[" type *("," type) [","] "]"]
qual-ident = ident ["." ident]

block      = "{" *NL [stmt *(1*(NL / ";") stmt) *(NL / ";")] "}"
stmt       = defer-stmt / for-stmt / ident ":" for-stmt
           / ident ":" type "=" expression
           / ident 1*("," postfix) "=" expression
           / expression [assign-op expression]
assign-op  = "=" / "+=" / "-=" / "*=" / "/=" / "%=" / "&="
           / "|=" / "^=" / "<<=" / ">>=" / ">>>="
defer-stmt = "defer" block
for-stmt   = "for" block
           / "for" for-bind "in" expression [".." expression]
             block
           / "for" expression block
for-bind   = [ident ","]
             (ident / "(" ident *("," ident) [","] ")")

expression = or-expr ["??" expression]
or-expr    = and-expr *("||" and-expr)
and-expr   = cmp-expr *("&&" cmp-expr)
cmp-expr   = bor-expr [cmp-op bor-expr]
cmp-op     = "==" / "!=" / "<" / "<=" / ">" / ">="
bor-expr   = xor-expr *("|" xor-expr)
xor-expr   = band-expr *("^" band-expr)
band-expr  = shift-expr *("&" shift-expr)
shift-expr = add-expr *(("<<" / ">>" / ">>>") add-expr)
add-expr   = mul-expr *(("+" / "-" / "+%" / "-%") mul-expr)
mul-expr   = unary *(("*" / "/" / "%" / "*%") unary)
unary      = ("-" / "!") unary / postfix
postfix    = primary *("." (ident / int-lit) [args]
           / "[" expression "]" / "?")
args       = "(" [arg *("," arg) [","]] ")"
arg        = [ident ":"] ["&"] expression
primary    = closure / int-lit / float-lit / str-lit
           / "true" / "false" / lock-expr
           / qual-ident [args]
           / "(" expression ")"
           / "(" expression 1*("," expression) [","] ")"
           / "[" [expression *("," expression) [","]] "]"
           / block / "scope" block / if-expr / select-expr
           / match-expr / "return" [expression]
           / "break" [ident] / "continue" [ident]
closure    = "|" [ident *("," ident) [","]] "|" expression
           / "||" expression
if-expr    = "if" expression block ["else" (if-expr / block)]
lock-expr  = "lock" expression "as" ident block
match-expr = "match" ["take"] expression "{" *sep
             [arm *(1*sep arm) *sep] "}"
arm        = pattern "=>" expression
pattern    = pat1 *("|" pat1)
pat1       = ident ":" type
           / qual-ident ["(" [pattern *("," pattern) [","]] ")"]
           / "(" pattern 1*("," pattern) [","] ")"
           / str-lit / ["-"] int-lit / "true" / "false"
select-expr = "select" "{" *sep [sel-arm *(1*sep sel-arm) *sep]
             "}"
sel-arm    = ident "<" "-" expression "=>" expression
           / "after" expression "=>" expression
           / "done" "=>" expression
```

关于语法的说明：

- 下一个 token 不是 `NL`、`;`、`}`、`,` 或 `)` 时，`return` 带一个操作数。同一行里后面跟着标识符时，`break` 和 `continue` 带标签。
- `lock` 只在后面跟着标识符时才是 lock 表达式；`defer` 只在后面跟着 `{` 时才是语句；语句 `ident ":" for-stmt` 只在冒号后面是 `for` 时才是带标签的循环。
- 解构语句的第一个目标必须是变量。
- 不带实参的大写开头的名字是没有字段的变体或结构体。
- 参考实现的解析器不要求结构体的字段、枚举的变体、接口的方法之间有分隔符；程序应当写上。

## 附录 B. 已知的偏差和未解决的问题

本附录列出本文和 `lark1` 之间已知的差异，以及还没有解决的限制。

1. **临时值的字段引起内部错误**：把调用结果的字段作为实参传递，例如 `f(g(x).field)`，`lark1` 会因内部错误（“从字段或下标移出”，在 `compiler/cg_expr.lark` 的 `owned_place` 里）停下，既不编译这个程序，也不报告正常的错误。先把结果绑定到变量（`k = g(x)`，再 `f(k.field)`）可以避开。
2. **插值和花括号**：`#{ ... }` 的结尾是数 `{` 和 `}` 字节找到的，插值表达式里的字符串或字符字面量中的花括号也算在内。所以像 `"#{f("}")}"` 这样的表达式会在错误的地方切开。程序不应当在插值里写不配对的花括号。
3. **保守的别名判断**：规则 R7 和 R11 只看位置的根变量（第 24.3 节）。
4. **栈溢出**：不管是任务还是主线程，栈用完时进程都以段错误结束，没有专门的诊断。
5. **早先的描述**：非正式的描述 [DESIGN] 没有提到八进制字面量（`0o`）、`\e` 和 `\xHH` 转义以及字节顺序标记。本文以 `lark1` 为准，这些它都接受。
